# 結構碳排估算 介面規格

版本：v1（2026-10-28）
狀態：步驟 0 產出；GUID 一經寫入不可變更。

## 一、專案參數

新增兩個專案參數（`ParamTarget.Project`，類別 `OST_ProjectInformation`），與既有 23 個參數一起建立，合計 25 個。

| 名稱 | 型別（SpecTypeId） | GUID | 說明 |
|---|---|---|---|
| `LEBR_CFs` | `SpecTypeId.Number` | `0dbc1252-2e5a-4ac7-b058-b97057d16078` | 估算後的主結構 CFs（kgCO2e）。有值時作為設計案 CFs，取代 Sp、F 計算。 |
| `LEBR_EstimateJson` | `SpecTypeId.String.Text` | `e901a98d-f808-4b97-954c-a141e504b939` | 估算紀錄（JSON）：材料選擇、數量、樓層、鋼筋來源、結果。 |

規則：
- 未勾選「使用估算」時，不寫入 `LEBR_CFs`，引擎依原本的 Sp、F 計算。
- `LEBR_CFs` 為 0 或未填時視為未估算（`Number()` 讀取時 0 視為未填）。
- GUID 寫入 `LebrParameters.cs` 時必須與上表完全一致。

## 二、估算輸入（`csharp/Estimate/StructureEstimator.cs`）

`EstimateItem`

| 欄位 | 型別 | 單位 | 說明 |
|---|---|---|---|
| `Source` | string | — | 來源品類，例如 `StructuralColumns`、`StructuralFraming`、`Floors`、`Walls`、`Rebar` |
| `Level` | string | — | 樓層名稱（同名必須同標高） |
| `ElevationM` | double | m | 樓層標高。小於 0 為地下層，其餘為地上層。 |
| `Quantity` | double | 見 `Unit` | 數量，不可為負 |
| `Unit` | string | `m3`（混凝土）、`kg`（鋼筋） | 必須與附錄單位一致，否則報錯 |
| `MaterialId` | string | — | 附錄一材料編號，例如 `PLCC-040` |
| `IsRebar` | bool | — | true 為鋼筋（使用 M），false 為混凝土（使用 L） |

## 三、估算輸出

`EstimateResult`

| 欄位 | 說明 |
|---|---|
| `Levels` | 各樓層的 `ConcreteM3`、`RebarKg`、`CFc`、`CFr`、`CFsn`，依標高排序 |
| `Above` | 地上層 CFsn 加總 |
| `Below` | 地下層 CFsn 加總 |
| `CFs` | `Above + Below`，寫入 `LEBR_CFs` |
| `Notes` | 無鋼筋樓層（Bn = 0）、手冊數字不一致的材料、無數量等說明 |

`LEBR_EstimateJson` 內容（草案）：

```json
{
  "version": 1,
  "calculated_at": "yyyy-MM-ddTHH:mm:ss",
  "model": "模型檔名",
  "levels": [ { "name": "", "elevation_m": 0, "concrete_m3": 0, "rebar_kg": 0, "cfs_n": 0 } ],
  "selections": [ { "source": "StructuralColumns", "material_id": "PLCC-040", "unit": "m3", "quantity": 0 } ],
  "rebar_sources": { "structure_rebar": "Rebar（主體柱、梁）＋ OST_AreaRein／OST_PathRein（樓板）" },
  "result": { "above": 0, "below": 0, "cfs": 0 },
  "notes": []
}
```

## 四、引擎接入點（`csharp/LebrEngine.cs`）

- 新增輸入欄位：`ProjectSettings.StructureCFs`（`double?`，JSON 名稱 `structure_CFs`），由 `RevitQuantityProvider` 從 `LEBR_CFs` 讀取。
- `LebrCalculator.CalculateStructure`：
  - 若 `StructureCFs` 有值（大於 0）：`result.Design.CFs = StructureCFs`，設計案主結構視為完整，不檢查 Sp、F。
  - 不再對這個值套用 Lccr 與 Rn（規則 8）。
  - 其餘（基準案 CFsc、施工、拆除、LL、減碳優惠）不變。
- 附錄三驗證：未填 `structure_CFs` 時，結果必須與改版前完全相同（CFs 12,934,263、CFR 20.51%、1+）。

## 五、Revit 數量來源（`revit-addin/Revit/`）

| 數量 | 品類（英文內部名稱） | 說明 |
|---|---|---|
| 結構柱 | `StructuralColumns` | 體積；依基準樓層歸屬 |
| 結構梁 | `StructuralFraming` | 體積；依參考樓層歸屬 |
| 樓板 | `Floors` | 全部納入（不限結構樓板）；依所在樓層歸屬 |
| 混凝土類結構牆 | `Walls` | 僅 `結構 = 是` 且為混凝土類 |
| 柱、梁鋼筋 | `Rebar`（主體為 `結構柱`、`結構構架`） | 依主體樓層歸屬 |
| 樓板鋼筋 | `OST_AreaRein`、`OST_PathRein` 的系統內鋼筋（`GetRebarInSystemIds()`） | 依主體樓板樓層歸屬，與柱、梁鋼筋加總為結構鋼筋 |

鋼筋質量計算：
- 質量（kg）＝ 鋼筋體積（`Rebar.Volume`，m³）× 7850 kg/m³。
- 已用模型驗證：鋼筋體積 3572.66 cm³ × 7850 = 28.04 kg，與「鋼筋質量」一致。
- 樓板鋼筋的系統內鋼筋會先記下，不在一般鋼筋中重複計入。

MCP 查詢注意事項：
- 必須使用英文內部名稱或 `OST_` 前綴名稱。`AreaReinforcement`、`Area Reinforcement`、`PathReinforcement` 會回報「無法辨識品類」；`OST_AreaRein`、`OST_PathRein` 可以辨識。
- 目前測試模型 `NCKU_9hours_intro_course_step8.rvt`：`Rebar` 765 支（主體柱 382、梁 383），`OST_AreaRein` 0、`OST_PathRein` 0。
