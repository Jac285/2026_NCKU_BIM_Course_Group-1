## 一、已確認的規則

| # | 項目 | 規則 |
|---|---|---|
| 1 | 估算範圍 | 地上與地下分開計算後加總。標高 < 0 為地下，其餘為地上。 |
| 2 | 混凝土數量 An | 結構柱、結構梁、**所有樓板**、**混凝土類結構牆**。非結構牆不計入。 |
| 3 | 鋼筋數量 Bn | **結構鋼筋 = 柱與梁的鋼筋 + 樓板鋼筋**。樓板鋼筋來自正式模型中的區域配筋或路徑配筋。 |

| 5 | 係數 L、M | 取附錄一 P-LCC 的 `total_a1_a4`。混凝土依下拉選單選擇的材料（例如 3000 psi）決定。不另外顯示混凝土強度。 |
| 6 | 公式 | CFsn = An × L + Bn × M；地上、地下各自加總後合計為 CFs。 |
| 7 | 回傳 | 勾選「使用估算」後，CFs 顯示在表單勾選格下方，並**儲存兩個專案參數**，傳回原計算引擎的設計案 CFs。 |

## 四、樓板鋼筋來源（方式 C）

- 正式模型中，樓板以區域配筋（Area Reinforcement）或路徑配筋（Path Reinforcement）建立鋼筋。
- 數量擷取時，樓板鋼筋與柱、梁鋼筋一併列入結構鋼筋，依主體樓板所在樓層歸屬。
- 品類查詢需使用英文內部名稱。MCP 的 `query_elements` 無法辨識「AreaReinforcement」，實作前需確認正確的品類名稱或改用 Revit API（見步驟 0）。

**說明**
- 「輸出 Token」是我生成的內容（程式、文件、回報），按實際生成量估算。
- 「總處理 Token」是每次呼叫時送入的上下文總量。在同一對話中，每一輪都會重新處理前面的內容，因此總量遠大於輸出量。
- 需要人工參與的部分不計入 Token：Revit 2024 實測、正式模型樓板鋼筋建模、PR 審查。

**降低用量的建議**
1. 每個步驟開新對話，只帶入該步驟需要的檔案與開發計畫。
2. 依賴的資料（附錄 CSV、公式）先整理成精簡摘要，避免重複讀取大檔。
3. 讀取大型檔案時先用 `grep` 定位，再讀取需要的行範圍。
4. 建置輸出只回報錯誤行，不貼完整日誌。
5. MCP 測試結果只擷取必要欄位（例如 `returnFields`）。
